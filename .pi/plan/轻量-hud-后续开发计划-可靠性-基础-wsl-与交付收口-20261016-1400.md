# 轻量 HUD 后续开发计划

## 1. 目标与当前基线

**只做三件事：看一眼状态、需要介入时提示、快速回到终端。** 完整性以可靠、省心、低占用衡量，不以功能数量衡量。

当前基线为已推送的 `3348a42`（`feat/m3-window-placement`），工作区干净；M3-A 位置保存已完成开发版验证。`STATE.json` 当前为空闲。Windows 真实 Agent、基础 WSL、物理多屏与长期性能仍未验收。

本次只制定计划。批准后先启动第一批，不一次铺开全部阶段。

### 范围约束

- 保留现有 Compact / Active / Attention / Expanded、1+N、手选 / Auto、托盘、隐私设置；不重做界面。
- 图钉继续只表示窗口置顶，不新增会话 Pin。
- 不做通知收件箱、历史数据库、时间线、搜索分组、报表、账户、云同步、控制面或通用插件平台。
- 不默认采集或保存 Prompt、回复、命令、文件内容及完整路径；未知信息保持未知。
- 本轮路线不包含声音、系统通知、磁吸、Git diff、更多 Agent 或 tab 级跳转；只有实际使用证明必要时才另开小任务。

## 2. 开发顺序

| 批次 | 目标 | 完成后得到什么 |
|---|---|---|
| 第一批 | Windows 核心闭环可信 | 现有两个 Agent 的状态、提示与返回行为有真实证据 |
| 第二批 | 最小 WSL 支持 | 一个明确启用的发行版能与 Windows 会话同时显示 |
| 第三批 | 简单接入与安装 | 普通用户无需 Node / Rust，也无需手工编辑 Hook JSON |
| 第四批 | 桌面与性能收口 | 可以长期留在托盘运行的轻量开发工具 |

每批验收后停止扩展，只处理本批发现的具体问题，再进入下一批。

## 3. 第一批：Windows 核心闭环可信——下一轮直接执行

### 工作内容

1. **修正状态语义。** 当前 `src/state.ts` 将 Done 描述为任务已完成；改为本轮结束语义，核对后端及其他展示文案，不暗示任务通过验收。保留 Activity / Attention 分离，不把 Idle、断线或超时当 Done，不为显示流畅伪造工具运行。
2. **说明为什么没有会话。** 在现有空态和 Collector 面板区分已连接但无会话、等待首个 Hook、连接失败、已确认的能力限制。无法从证据判断是否安装 Hook 时写等待验证，不猜未安装或已接入。
3. **完成真实 Agent 验收。** 先记录本机实际版本和启动方式，再覆盖首次启动、两个 Agent 并行、工具调用、明确 Waiting / 解除、错误、本轮结束、退出、resume 与断线。只修真实用例证明的缺陷；不以增加代理调用、启动 daemon 或接管审批来填补事件缺口。
4. **验证返回终端。** 测试用户实际使用的 Windows Terminal / VS Code 场景；可确认时返回，歧义、窗口关闭和身份变化时拒绝。失败原因沿用现有提示区域，不增加映射管理页。
5. **保留简单提醒。** Waiting / Error / 本轮结束仍使用现有 HUD 状态。重复和晚到事件不反复抢主卡，不破坏手选；会话结束及时移除，不为提醒建立历史会话存储。

### 文件范围

- 直接涉及：`src/state.ts`、`src/App.tsx`、`src/Panels.tsx`、必要的 `src/Hud.tsx` / `src/model.ts`，以及相应 `tests/frontend-*.test.*`。
- 仅在复现缺陷时修改：`src-tauri/src/collector.rs`、`hooks.rs`、`codex_live.rs`、`codex.rs`、`native.rs`。
- 复用 `scripts/verify-native.cjs`、`scripts/verify-window.ps1`；在 `docs/m2-event-coverage.md` 和 `docs/m2-verification.md` 追加明确标注的新版本证据，不覆盖历史结果。

### 验收与停止条件

- 展示文案与来源事实一致，旧事件不覆盖新状态，历史文件不冒充活跃会话。
- 明确记录受支持版本、模式与真实测试结果；不把未覆盖模式笼统称为完整支持。
- 多会话不会相互清理或改变用户手选；返回失败不会唤醒其他窗口。
- 前端检查、受影响 Rust 回归、Release 和相关原生检查通过。
- 真实模型调用或配置授权未就绪时，可完成代码与隔离验证，但本批保留真实验收未完成状态，不宣称通过。

## 4. 第二批：最小 WSL，不建设跨平台框架

### 支持范围

首版只接入一个用户明确启用的 WSL2 发行版和一个普通用户；先 Claude，再 Codex。不会自动枚举并启动所有发行版，不支持容器、SSH、其他 Linux 用户或多发行版管理界面。

### 最小实现

- Linux 本地采集、脱敏；Windows 通过参数数组启动指定 helper，以专用标准输入 / 输出管道通信。不监听网络端口，不扫描 `\\wsl.localhost\`。
- 首版采用**版本握手 + 状态变化时发送完整来源快照 + 必要诊断**。连续变化可合并，帧和队列有明确上限；不先做增量事件总线、确认重放、持久化队列或复杂重同步协议。
- Windows 为连接绑定来源身份；每份快照只替换该来源会话。旧连接回调失效，错误协议明确断开。EOF / helper 退出只移除 WSL 来源，不伪造 Agent Done；重连重新读取现状。
- helper 随 HUD 控制管道关闭而退出，不安装常驻服务；发行版退出后不自动反复唤起。连接存活检查如确需引入，仅用于采集健康，不用于推测 Agent 状态。
- 跨界只传白名单元数据；缺少路径、模型或容量就保留缺失语义。Linux PID 不进入 Windows 窗口返回；WSL 返回按钮明确不可用。
- 仅提取两端确实复用的模型和解析逻辑，不顺带重构 Windows 窗口层。

### 文件范围

- 新增最小纯 Rust `crates/hud-core/` 与无 GUI 的 `crates/hud-wsl/`，以及 Windows `src-tauri/src/wsl.rs` 接收入口。
- 调整 `src-tauri/src/model.rs`、`collector.rs`、`codex.rs`、`lib.rs`、相关 Cargo 配置；尤其修正 `sync_codex` 当前按 Agent 类型全量清理会话的问题。
- 同步 `src/model.ts`、`src/Panels.tsx`、`src/Hud.tsx` 的来源标记、诊断和字段缺失展示。
- 在现有 CI 增加必要的 Linux core / helper 检查，不建立通用适配器平台。

### 验收与停止条件

- Windows / WSL 同名会话、相同数值 PID 不冲突；断开一端不影响另一端。
- 支持的 Claude / Codex 各完成真实发现、状态、退出 / 恢复验证；未知容量不显示虚假百分比。
- 原始正文、命令与 transcript 路径不进入管道和诊断；HUD 退出无自建 helper 残留。
- 单发行版闭环通过即停止扩展。Linux CI 和模拟管道不能替代真实 WSL 验收。

## 5. 第三批：简单接入与安装

### 用户体验

保留一个现有 Collector 面板，不做多页接入向导。只提供必要状态、检查，以及用户主动触发的接入 / 移除操作。

### 实现范围

- 将现有 Node 配置脚本中的最小 Hook 合并 / 卸载能力移入 Rust：备份原字节、保留其他 Hook、重复执行不重复添加、精确卸载、检测并发修改、失败保留原配置。
- UI 确认后才写明确选定的配置；无参数 Hook helper 继续保持原事件入口，不输出审批决策。已有脚本保留兼容，不让终端用户额外安装 Node。
- 只维护一种当前用户安装方式：Tauri NSIS 安装包，包含 HUD 和 helper，使用稳定路径；测试升级后 Hook 路径仍有效、卸载不破坏其他配置。
- 加入单实例与默认关闭的开机启动开关。用户明确启用才注册，禁用 / 卸载精确移除本产品项。
- 第一版手动下载安装包升级，不加入自动更新服务、账户或常驻维护进程。

### 文件范围

`src-tauri/src/hooks_config.rs`（新增）、`src-tauri/src/bin/agent-hud-hook.rs`、`app.rs` / `native.rs`、`src/Panels.tsx`、`src/native.ts`、`src-tauri/tauri.conf.json`，必要的安装配置及测试；复用 `scripts/configure-claude-hooks*.cjs`、`unconfigure-claude-hooks*.cjs` 的测试场景作为行为基准。

### 验收与停止条件

- 无 Node / Rust 开发工具的 Windows 环境可安装、启动并接入。
- 未经确认不修改 Agent 配置；重复安装 / 卸载安全，升级不留下无效 Hook，单实例不重复采集。
- 开机启动可明确开关，卸载不删除用户的其他配置或会话数据。
- 无签名身份时只能交付明确标注的未签名测试包；正式分发的签名和发布单独授权，不因此增加账户或付费体系。

## 6. 第四批：桌面与性能收口，达到条件就冻结功能

### 必测场景

- 物理拖动、Alt 临时交互、托盘恢复、穿透、取消置顶、输入焦点不被抢。
- 多屏负坐标、125% / 150% / 200% 与混合 DPI、拔屏恢复；设备缺失时明确记录未验收。
- 连续 8 小时运行，反复启动 / 退出会话；统计 HUD、WebView、proxy 与 WSL helper 的总体资源，不只看主进程。
- 无活跃会话时无高频轮询，历史文件增长不引起持续内存增长；HUD 退出回收自身子进程。

### 测量标准

沿用已有目标：空闲 CPU < 1%、可观察来源的会话发现 < 2 秒、事件到达采集入口后的 HUD 响应 < 500 ms。报告测量环境、CPU 统计口径、采样方法及内存趋势；源端事件延迟单列，不能通过排除慢事件假装达标。

### 文件范围

扩展 `scripts/verify-window.ps1`、`scripts/verify-placement.cjs`，新增隔离性能测量脚本和对应验证说明。`placement.rs`、`native.rs`、`collector.rs` 只修实测问题，不顺便增加动画、磁吸或其他功能。

完成条件：受支持环境的核心闭环、安装 / 卸载、桌面交互和性能通过，限制已写清。此后进入维护期：修缺陷、跟进必要版本兼容，不再自动追加功能。
